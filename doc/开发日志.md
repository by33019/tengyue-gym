# 腾跃健身 - 开发日志

> 项目：校园健身打卡智能计划助手 (SpringBoot3 + Vue3 + MySQL8 + Redis + Coze Agent)

## 初始状态评估

- 10 个模块中 9 个前后端完整实现
- 核心待办：AI 智能模块（Coze Agent 集成）
- 4 个基础设施问题：schema 字段缺失、MinIO 未纳入 compose、缺 .env、ai_call_log 无代码

## 第一阶段：基础设施修复

修复了 4 个问题：
1. `sql/schema.sql` 补齐 `user.is_anonymous`、`plan.is_template` 字段

4. 为 `ai_call_log` 表创建 entity/mapper/service

## 第二阶段：AI Coze Agent 模块

### 后端实现
- `CozeSseEmitterImpl` — Spring SseEmitter 封装，30s 超时
- `ContextBuilderImpl` — 组装用户身体数据 + 近 7 日运动摘要
- `CozeClientImpl` — HTTP 调用 Coze `stream_run` API，逐行解析 SSE
- `AiService` — 编排层：限额检查 + 10 分钟缓存 + session 管理 + 兜底文案
- `AiController` — 6 个端点（chat/plan/analyze/recipe/exercise-guide + quota）
- `AiCallLogService` — 每日 10 次限额 + 调用日志

### 前端实现
- `api/ai.ts` — SSE 客户端
- `AiPage.vue` — 功能卡片 + 对话流 + 打字机效果

### Coze API 踩坑记录
1. 请求体格式错误 → 参考 `doc/gym_coze.py`，正确格式为 Coze Workflow API：
   ```json
   {"content":{"query":{"prompt":[{"type":"text","content":{"text":"..."}}]}},"type":"query","session_id":"...","project_id":"..."}
   ```
2. Spring Boot 不自动加载 `.env` → 启动时需显式设置环境变量：
   ```bash
   COZE_API_TOKEN="..." COZE_API_URL="..." COZE_PROJECT_ID="..." mvn spring-boot:run
   ```
3. SSE 响应解析字段路径为 `content.answer`（非 `message`）
4. 前端流式渲染需加 15ms 逐字延迟才有打字机效果
5. RestTemplate 回调方式导致 401 → 改用 `HttpURLConnection` 直接发请求

## 关键经验

1. Spring Boot 不自动加载 `.env`，本地开发需显式 export 或用 dotenv 库
2. MyBatis-Plus 默认不更新 null 值，需用 `LambdaUpdateWrapper.set()` 显式设 null
3. Coze Workflow API 与 Chat API 请求体格式完全不同，需查阅实际 SDK 代码
4. 前端 SSE 流式渲染需加 `setTimeout` 延迟才能看到打字机效果
5. Vue `reactive` 对象传给 axios 可正常序列化，无需额外处理
6. 角色重构时要同步改路由守卫 + 侧边栏 + 底部导航 + 后端校验，缺一不可
